# GUI Feedback — 2026-07-24

Distilled feature requests and enhancements from a collaborator using SageGUI.
Source for the Phase 5 / Phase 6 planning in [PLAN.md](../PLAN.md). Kept verbatim
here so the original feedback is preserved outside the chat.

---

## 🛠️ Feature Requests & Enhancements

### 1. File Input & Preprocessing

* **Direct Vendor File (.raw) Support:**
  * **Need:** Users currently have to manually convert `.raw` files to `.mzML` beforehand, which takes up to an hour per batch.
  * **Feature:** Automatic/integrated conversion of `.raw` (and potentially other vendor formats) directly into SageGUI or passing them directly to the search pipeline.

* **On-the-Fly FASTA Concatenation:**
  * **Need:** Users need to search multiple database files at once (e.g., target organism + contaminants, or multiple species). Currently limited to selecting a single `.fasta` file.
  * **Feature:** Support selecting/adding multiple `.fasta` files into a single run.

* **Built-in Contaminants Database:**
  * **Need:** Frequently adding common contaminants (e.g., cRAP database) manually is friction for users.
  * **Feature:** Pre-packaged toggle/option to automatically append standard contaminants to the search database.

---

### 2. Output Formatting & Ecosystem Integration

* **Format Export/Spoofing for Downstream Tools:**
  * **Need:** Output needs to easily load into existing downstream visualization and quant tools (Scaffold, MSstats, FragPipe Analyst, etc.).
  * **Feature:** Export Sage output into native or spoofed formats compatible with:
    * **Scaffold**
    * **MSstats**
    * **FragPipe Analyst**

* **Downstream Summarization & Rollups:**
  * **Need:** Raw peptide-level output (e.g., accession numbers tied to peptides) isn't intuitively actionable for non-computational biologists.
  * **Feature:** High-level protein intensity/quantification rollups (e.g., *"Protein X in Sample 1 vs. Sample 2"*) directly inside the GUI or via quick export.

---

### 3. Search Configuration & Usability

* **Expanded Modifications List:**
  * **Need:** Adding custom modifications manually can be tedious or difficult.
  * **Feature:** Provide a broader preset library/dropdown of common variable and static modifications.

* **GUI Session & Timeout Resilience:**
  * **Need:** Long background processes (like 1+ hour conversion tasks) cause the GUI to freeze or appear unresponsive ("not responding").
  * **Feature:** Asynchronous execution with progress indicators to prevent UI freezes, along with session retention/auto-recovery.

## Follow-up feedback (during live use)

* **`bucket_size` dial is confusing.** A collaborator using the GUI found the bucket-size setting unclear. It's a pure performance knob (no effect on results) — see NOTES.md "Reference → Sage parameter notes → `bucket_size`" for the explanation. **Takeaway:** every GUI control needs an inline description/tooltip or a link to documentation. This generalizes beyond bucket_size — see the parameter-documentation item added to Phase 5.

* **Standard modifications** the collaborator expects as presets (feeds the "Expanded modifications preset library" Phase 5 item):
  * Variable: oxidation on M (`oxM`); oxidation on P (`oxP`) for skin/collagenous samples; pyro-Glu on peptide N-term Q/E; deamidation on N/Q; acetyl on protein N-term.
  * Fixed: carbamidomethylation (+57) on C.
  * See NOTES.md "Reference → Sage parameter notes → variable/static mod syntax" for the exact Sage config encoding.
